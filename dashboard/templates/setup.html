llmproxy — Setup & Überblick

Architektur, Client-Einrichtung, Monitor-App, Bearer-Auth & Konfiguration.

🏗 Wie das zusammenhängt
Dein Rechner / Roo Cline / Open WebUI / App | | Authorization: Bearer <token> (optional, für named clients) | :11435 <-- immer dieser Port, nie :11434 direkt! v +------------------------------------------------------------+ | llmproxy (<proxy-host>, systemd) | | - Bearer-Token-Auth (clients.yaml) | | - Logging (SQLite), Budgets pro Client | | - Guardrails / DLP / Fail2Ban | | - Gaming-Mode & Ollama-Lock (GPU für ComfyUI frei) | | - Frontier-Proxy (externe OpenAI-kompatible APIs) | | - Auto-Fallback (Ollama down → Frontier) | | - Idle Model Eviction | | - /status/stream (SSE live feed) | +------------------------------------------------------------+ | | :11434 / :11438 (intern) v Ollama (lokal auf <gpu-host>, 2x GPU)
✗ http://<gpu-host>:11434 — direkt zu Ollama, nicht verwenden — kein Logging, keine Sperre, kein Budget
✓ http://<proxy-host>:11435 — llmproxy, immer dieser Port

Der Proxy ist für Ollama-kompatible Clients vollständig transparent — du änderst nur die URL von :11434 auf :11435.

🔑 Bearer-Token-Authentifizierung

Jeder Client kann (optional) mit einem API-Token konfiguriert werden. Ohne Token wird der Client über seine IP-Adresse identifiziert. Tokens werden direkt in clients.yaml gespeichert und im Dashboard unter Admin → Clients verwaltet.

Anfrage mit Token (named client)
curl http://<proxy-host>:11435/v1/chat/completions \
  -H "Authorization: Bearer <dein-token>" \
  -d '{"model":"llama3.2","messages":[...]}'
Anfrage ohne Token (IP-basiert)
curl http://<proxy-host>:11435/v1/chat/completions \
  -d '{"model":"llama3.2","messages":[...]}'
→ Wird dem Default-Client oder der Sender-IP zugeordnet

Token generieren: Admin → Clients → Zeile des Clients → Generate. Oder per CLI: python3 scripts/generate_tokens.py

⚙️ Admin-Features im Überblick
👥
Clients & Budgets
Bearer-Token, tägliches Token-Limit (lokal & Frontier getrennt), erlaubte Modelle, Block-Status.
🛡️
Safeguards / Guardrails
Prompt- & Output-Filter (Keyword, Regex, DLP). Aktionen: Deny, Warn, Rewrite. Fail2Ban-Autosperre.
🌐
Frontier LLMs
Externe OpenAI-kompatible Provider (Gemini, OpenRouter) als Fallback oder direkt.
🔒
Ollama-Lock
Sperrt lokale GPU-Nutzung und entlädt Modelle. Automatisch bei laufender ComfyUI-Queue.
🔀
Auto-Fallback
Ist Ollama nicht erreichbar → transparent auf Frontier-Modell umleiten.
📋
Admin-Audit-Log
Alle Admin-Aktionen mit Zeitstempel, Quelle und IP protokolliert.
💶
Chargeback
Kosten-/Leistungsverrechnung pro Client, mit IP-Drilldown und CSV/XLSX-Export. Eigener API-Token.
💶 Chargeback-API (Kosten-/Leistungsverrechnung)

/admin/chargeback/{summary,drilldown,detail,export} liefert Token-/Kostenaufschlüsselung pro Client (token_name), inkl. Drilldown auf die einzelnen Client-IPs, die für diesen Client angefragt haben — sichtbar im Dashboard unter Chargeback. Kosten werden nur für externe Frontier-LLMs berechnet (aus config/pricing.yaml, €/1k Tokens pro Modell); lokale Ollama-Modelle sind immer 0€. Modelle ohne Preiseintrag werden als unpriced_models markiert statt stillschweigend mit 0€ gezählt zu werden.

Zugriff mit eigenem Chargeback-Token (read-only, z.B. für BI-/Buchhaltungstools)
curl http://<proxy-host>:11435/admin/chargeback/summary \
  -H "X-Chargeback-Token: <token aus /opt/llmproxy/.chargeback_token>"
CSV/XLSX-Export
curl ".../admin/chargeback/export?view=summary&format=xlsx" \
  -H "X-Chargeback-Token: <token>" -o report.xlsx

Der Admin-Token (X-Admin-Token) funktioniert ebenfalls — der separate Chargeback-Token existiert nur, damit man Lesezugriff auf Kostendaten weitergeben kann, ohne volle Admin-Rechte zu gewähren. Beide Tokens liegen als Datei unter /opt/llmproxy/ (0600), nicht per API abrufbar.

⚡ <proxy-host> fährt automatisch hoch

llmproxy läuft auf <proxy-host> als systemd-Service und startet automatisch mit dem System — du musst nichts manuell starten.

Status prüfen
systemctl status llmproxy
Logs ansehen
journalctl -u llmproxy -f
Neu starten
systemctl restart llmproxy
Health-Check
curl <proxy-host>:11435/health
🖥 Was der LLM Monitor zeigt & kann
🎮
Gaming-Mode-Anzeige
Sobald Steam auf dem <gpu-host> läuft, sperrt llmproxy alle LLM-Anfragen und der Monitor zeigt einen roten „GAMING MODE"-Banner. Anfragen liefern dann HTTP 503.
🖥️
Hardware-Live-Stats
CPU-Auslastung, RAM-Nutzung, sowie pro GPU: Auslastung in %, VRAM belegt/gesamt als Balken, Temperatur in °C — alles live via SSE, kein SSH nötig.
🤖
Geladene Modelle
Welche Modelle gerade im VRAM liegen, mit Größe und Context-Länge. Farbkodierung nach VRAM-Anteil (grün → gelb → rot).
📊
Token-Statistiken (Session)
Tokens In/Out seit Programmstart, aktuelle tokens/s (In und Out getrennt), Peak-tps. Wird aus dem Live-Feed akkumuliert.
🔔
Benachrichtigungen (Tray-Toast)
Neue Notifications aus dem llmproxy (Gaming-Mode, Budget-Warnung, TPS-Anomalie, Eviction …) erscheinen als Desktop-Toast. Das Tray-Icon zeigt einen Badge bei ungelesenen Meldungen.
🔗
Verbindungsstatus & Reconnect
Zeigt ob der SSE-Stream aktiv ist. Bei Verbindungsabbruch reconnected die App automatisch alle 3 Sekunden.
📥
Minimize-to-Tray
Fenster schließen versteckt den Monitor im Tray — läuft weiter im Hintergrund. Tray-Icon: Klick = Fenster öffnen, Rechtsklick = Menü mit „Anzeigen" und „Beenden".

⚡ One-Liner Installation

Auf dem Zielrechner ausführen — lädt, entpackt und installiert automatisch:

mkdir -p /tmp/llm-monitor && cd /tmp/llm-monitor && curl -fsSL http://{{ request.headers.get('host', ':18080') }}/static/llm-monitor-setup.tar.gz | tar xz && bash install_monitor.sh --url {{ proxy_url }}
📋 Manuelle Installation
  1. 1
    Archiv herunterladen & entpacken
    mkdir -p /tmp/llm-monitor && cd /tmp/llm-monitor
curl -fsSL http://{{ request.headers.get('host', ':18080') }}/static/llm-monitor-setup.tar.gz | tar xz
  2. 2
    Installer ausführen
    bash install_monitor.sh --url {{ proxy_url }}

    --url muss auf den llmproxy zeigen. Voreingestellt: {{ proxy_url }}

  3. 3
    App starten
    Anwendungsmenü → LLM Monitor
    Terminal: llm-monitor
